# Finance RAG — Quarterly Financial Reports

## Overview

Finance RAG is a beginner-friendly Retrieval-Augmented Generation (RAG) application
built for an investment advisory research workflow. Analysts upload quarterly
financial-result PDFs for a listed company (Infosys, in this project), ask
questions in plain English, and get answers generated by GPT-4o that are
grounded strictly in the uploaded documents — with the source PDF filename
and page number shown for every answer so it can be verified.

## Problem Statement

Reading through several quarters of financial-result PDFs to answer a single
question — "What was the operating margin last quarter?", "Was a dividend
declared?" — is slow and error-prone when done manually. Analysts need a way
to ask natural-language questions and get answers that are traceable back to
the exact page of the exact report, without the risk of the assistant
inventing numbers that aren't actually in the source documents.

## Solution

```
PDF
 ↓
Text extraction (page by page)
 ↓
Chunking (RecursiveCharacterTextSplitter)
 ↓
Embeddings (OpenAI text-embedding-3-small)
 ↓
ChromaDB (persistent vector store)
 ↓
Similarity search (top 4 chunks)
 ↓
GPT-4o (temperature 0.1, context-only answering)
 ↓
Answer + Sources
```

## Features

- Multiple PDF upload via the Streamlit sidebar
- One-click PDF indexing (extraction → chunking → embeddings → storage)
- Recursive character-based chunking (1200 chars, 200 char overlap)
- OpenAI embeddings (`text-embedding-3-small`)
- Persistent ChromaDB — indexed documents survive an app restart
- GPT-4o question answering (temperature 0.1 for consistency)
- Source citations with filename **and** page number, pulled from ChromaDB metadata
- Honest refusal — the app says so plainly when an answer isn't in the documents
- Clean, simple Streamlit UI
- Duplicate-safe ingestion — re-indexing the same PDF won't create duplicate chunks

## Tech Stack

| Technology | Purpose |
|---|---|
| **Streamlit** | Web UI for uploading PDFs and asking questions |
| **LangChain** | Orchestration: document loading, splitting, vector store, LLM calls |
| **PyPDFLoader (pypdf)** | Extracts selectable text and page numbers from PDFs (no OCR) |
| **RecursiveCharacterTextSplitter** | Splits page text into overlapping chunks for embedding |
| **OpenAI `text-embedding-3-small`** | Converts text chunks and questions into vector embeddings |
| **ChromaDB** | Persistent vector database for similarity search |
| **OpenAI GPT-4o** | Generates the final answer from retrieved context |
| **python-dotenv** | Loads the API key from a local `.env` file, keeping it out of source code |

## Chunking Strategy

- Chunk size: **1200 characters**
- Chunk overlap: **200 characters**

1200-character chunks provide enough surrounding financial context while the
200-character overlap reduces the chance of splitting important information
across chunk boundaries.

## Setup

1. **Clone the repository**
   ```bash
   git clone <your-repo-url>
   cd finance-rag
   ```

2. **Create a virtual environment**
   ```bash
   python -m venv venv
   ```

3. **Activate it**
   ```bash
   # macOS / Linux
   source venv/bin/activate

   # Windows
   venv\Scripts\activate
   ```

4. **Install requirements**
   ```bash
   pip install -r requirements.txt
   ```

5. **Create your `.env` file**
   ```bash
   cp .env.example .env
   ```

6. **Add your OpenAI API key** to `.env`:
   ```
   OPENAI_API_KEY=sk-...your-key-here...
   ```

7. **Put PDFs inside `data/`** (optional — you can also upload them through the UI)

8. **Run the app**
   ```bash
   streamlit run app.py
   ```

## How to Use

1. Upload one or more Infosys quarterly report PDFs in the sidebar.
2. Click **Index Documents** and wait for the confirmation message
   (e.g. "✓ 3 files processed", "✓ 214 chunks stored").
3. Type a question in the **Ask a Question** box.
4. Click **Ask** and view the generated answer.
5. Check the **Sources** section to verify which PDF and page the answer came from,
   and optionally expand **Retrieved Context** to see the exact text the model used.

## Persistence Test

ChromaDB is configured with a persistent storage directory (`./chroma_db`), so
the vector store is written to disk as soon as documents are indexed. To
verify persistence:

1. Start the app, upload PDFs, and click **Index Documents**.
2. Stop Streamlit (Ctrl+C).
3. Start Streamlit again (`streamlit run app.py`).
4. Ask a question **without** re-uploading or re-indexing anything.

If the answer comes back correctly with sources, persistence is working —
the previously indexed chunks were loaded from `./chroma_db` on startup.

## Limitations

- **Table extraction**: `pypdf`-based text extraction can occasionally
  mangle complex tables (e.g. multi-column financial statement tables),
  since it extracts text in reading order rather than preserving table
  structure.
- **No OCR**: scanned or image-only PDFs will not be readable; the app
  assumes selectable text, consistent with typical investor-relations PDFs.
- **Simple similarity search only**: there is no re-ranking or hybrid
  (keyword + vector) search, so very short or ambiguous questions may
  occasionally retrieve less-relevant chunks.
- **Fixed top-4 retrieval**: questions that require synthesizing information
  spread across many pages (e.g. a full 4-quarter trend) may not always pull
  in every relevant chunk.

## Future Improvements

- Add table-aware PDF extraction (e.g. `pdfplumber` table detection) for cleaner
  financial statement parsing.
- Allow the user to configure the number of retrieved chunks (top-k) from the UI.
- Add a "clear index" button to reset ChromaDB without deleting files manually.
